### 收益与退化

- 最大的单步耗时收益来自去除整站 JSON 中间树（−0.791 s）、Python 批量编码（−0.542 s）及共享语义定义（−0.471 s）。Renderer 直接构造与共享 HTML targets 两步合计减少约 0.586 s。
- 共享语义定义同时将 RSS 从 1421.0 降至 770.5 MiB，减少约 650.6 MiB；共享页面／目录值另减少约 478.3 MiB。

- 当前 3.548 s 仍比环境句柄优化版慢约 11.4%。资源重构以后的模块分层、comemo、移除 Markdown helper 及未提交语言能力，profile 主要阶段接近；小幅中位数差异和 CLI listen 控制点的浮动不作独立优化或回退结论。

## 3. comemo：同进程完整站点组装

同一个带 profiling feature 的二进制切换三种模式。每种模式三次进程，每次三轮新建 Vault；首轮计算缓存为空，后两轮保留进程级缓存。组装计时不含最后一次输出验证副本写盘。此 example 使用 FsResources 直接读取整份 Notist.toml，而普通 CLI 使用内存合成的 target 配置，两者的绝对组装时间不可互相相减；这里仅比较 example 内部的三种模式。

| 模式 | 首轮 ms（中位数／范围） | 后两轮 ms（中位数／范围） | 首轮 compile_work / bind_work 次数 | 后续 compile_work / bind_work 次数 |
| --- | ---: | ---: | ---: | ---: |
| baseline | 3062.42 (3061.56–3082.06) | 3028.73 (3011.32–3036.76) | 0 / 51739 | 0 / 51739 |
| compile | 3067.97 (3059.24–3074.51) | 3019.08 (2999.81–3032.90) | 0 / 51739 | 0 / 51739 |
| both | 3049.71 (3043.69–3067.16) | 3021.83 (3011.22–3059.94) | 0 / 0 | 0 / 0 |

XIV DB 生产模板站点没有 notc 导入，compile 实际执行为零。开启绑定缓存还包含空 BindingSpec 的共享空作用域 fast path；零 bind_work 不能表述为大量模块导入的缓存命中。三种模式的组装时间范围重叠，本轮未测得稳定的整站收益。普通 CLI 每次为新进程，不能用同进程热缓存解释其耗时差异。

## 5. 方法、可复现性与限制

- AMD Ryzen 9 9950X3D2 16-Core Processor；Linux-7.2.12-x86_64-with-glibc2.44；rustc 1.97.1；Python 3.14.8。
- CPU 8，频率策略 `{"scaling_min_freq": "614286", "scaling_governor": "powersave", "scaling_max_freq": "5665080", "scaling_driver": "amd-pstate-epp"}`；没有固定频率。
- release debug=0、incremental=0、jobs=2。每个普通版本独立 Cargo target；编译和正式计时不并发。曾发现共享 target 的旧源码时间戳误复用，初轮全部弃用，重新隔离构建后才测量。
- wall 含进程启动、Python prepare、Rust 管线、模板、文件发布及旧输出清理。温文件缓存、不做 fsync；不代表冷盘、增量构建或持久化写入速度。
- wait4 的 ru_maxrss 单位 KiB，非进程树同时内存总和。user/system 也按 wait4 口径记录。
- 前七个引擎恢复当时未提交的 publication 路径优化，避免拿未优化的平方级路径扫描当基线。存档 Handlebars 的上下文复用未提交源码未恢复，表中单独标明。
- Python 三档脚本通过消费者 git 历史提取；品牌、CSV、静态搜索索引、内容及输出路径固定，未引入后续项目更名。每个点是累计版本，收益与顺序有关，不能当成相互独立的优化收益。
- 当前工作区包括尚未提交的 str、arr.len、for 等语言能力，但这里仍运行同一生产模板负载。另一次约 53–56 s 的 notc 正文验收是不同宿主与页面模型，不作为本表回退基线。
- 结果目录：`/tmp/opencode/xiv-history-20261102`。普通二进制、源码快照、探针补丁、固定输入、逐次 stdout/stderr、wait4 原始记录与逐文件指纹均保留。
- `integrity.json` 记录样本数、二进制校验、工作区 diff 保全和同进程输出验证；`source-fingerprints.json` 保存每份源码快照的逐文件指纹；工具自身 6 项轻量回归通过。
