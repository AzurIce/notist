# 整站构建性能与热点评估：9a3c5f7

## 结论

本次冻结提交为 9a3c5f7bdaeaa8eca31b6160f140a8928704322c。
主要问题是百万级求值／内容物化操作携带的短命对象构造、堆分配与销毁，其次是宿主路径比较和重复树遍历。
不是最终页面模板渲染太慢，也没有证据支持继续优先扩大模块／数据解析缓存或名称整数化工程。

优先做减少无用构造的小型实验，再处理路径重复工作和遍历栈；不能把采样占比直接当作可获得的加速比例。
本轮仅测量和分析，没有改动生产实现，也没有实施优化。

## 操作热点：CPU 实际执行什么

CPU 比例是两次父进程采样的范围，不是包括扩展子进程的 wall 比例。
self 仅计最内层执行位置；inclusive 包含被调用工作，各行有重叠，不可相加。

| 操作／调用路径 | CPU 样本比例 | 解释 |
| --- | ---: | --- |
| glibc malloc／free／realloc 等自身 | 27.0～28.2% self | 堆管理本身已是显著成本 |
| 文档求值 run | 37.3～37.4% inclusive | 与阶段计时相互印证 |
| present 内容物化 | 约 35.8% inclusive | 含 execute、表达式及构造 |
| execute 调用路径 | 26.2～26.5% inclusive | 实参、字段、派发、构造与分配 |
| expr 表达式求值 | 13.6～13.7% inclusive | 是上述调用路径的一部分 |
| std::path::compare_components | 9.9～10.8% inclusive | 宿主文件路径／索引键比较，不是语言变量名比较 |
| HTML render_with_diagnostics | 7.0～7.5% inclusive | 正文阶段的一个子项 |
| Node::descendants | 3.6～4.4% inclusive | 含遍历栈分配与增长 |
| Dict::insert | 2.9～3.2% inclusive | 包含查找、键处理、容器及分配 |
| implementation 查找路径 | 2.9～3.1% inclusive | 包含特化键与缓存子项 |
| memcpy／memmove 自身 | 约 2.3% self | 不是全部克隆／复制的总成本 |
| 实例／编译期值 key | 约 1.5% inclusive | 不应与 implementation 重复相加 |
| 来源引用校验 | 1.0～1.3% inclusive | 不是首要热点，不应通过省略校验优化 |

路径比较涉及 Vault::ensure_environment、Assets::insert、DocumentIndex::find、ResourceSession::register_source、Files::inspect 和 publication::unchanged。
因此不能把这约一成 CPU 都归给正文链接，也不能认为为语言字段引入 Symbol 就能消除它。

## 频次与分配证据

detail 两次的主要调用次数一致：execute／implementation 各 6,073,286 次，present 8,440,426 次，bind_content 2,213,972 次，data.native 1,955,784 次。
present 含递归，不等于不同内容对象数量。
真实 data.parse 为 565 次，parse_hit 为 51,173 次；实际模块编译 1 次、bind_cached 3 次。
已有数据解析和模块绑定复用确实生效，主要问题在命中这些复用后仍需执行的百万级小操作。

分配 probe 精确统计父进程成功 API 调用：malloc 132,729,790 次、calloc 37 次、realloc 14,726,628 次。
这不是同时存活对象数量，也不是每次 realloc 都发生了物理复制。
malloc／calloc 以 1/2048、realloc 以 1/256 概率采集栈；以下按逆概率估计，不是逐调用点精确计数：

## 问题与优化优先级

### 第一优先级：高频通路的不必要构造

1. crates/notist-eval/src/eval.rs:1139：所有 execute 都先 Scope::new，但只有 code 分支使用输入环境。Scope 的共享容器即使为空也要分配。应实验将作用域构造及输入装配收敛到 Code 路径。
2. crates/notist-eval/src/eval.rs:1253、1375：先 item_shell 克隆字段／实例并构造空 children，紧接着覆盖 content；present 的 Element 路径也先产生空 children 再赋值。应考虑一次构造最终 payload，而非创建后丢弃中间容器。
3. crates/notist-core/src/shared.rs:434：Dict::insert 先 Into<String>，查不到再转换 Text；借用键会经历不必要的临时字符串构造，更新已有键也先构造字符串。可实验借用查找、仅在插入时创建最终键。
4. crates/notist-eval/src/eval.rs:171、656：单元素 Content 和递归 present 分别构造 Piece 存储、输出 Vec；宜先移除确定无用的中间对象，再评估是否需要更大范围的表示调整。

证据链是“百万级调用 + 大量对应分配 + 分配器显著 CPU + 源码中的冗余构造”，不是单凭函数名猜测。
仍需独立 A/B 才能量化收益；不能声称 28% 分配器 CPU 全部可消除。
必须保持实参求值与错误顺序、调用深度、内容／数据预算、来源链以及重复挂载的独立执行语义。

### 第二优先级：路径构造和有序索引的重复成本

src/resources.rs:483 的 normalize 逐分量增长 PathBuf；路径作为多处 BTreeMap／BTreeSet 的键反复比较。
应先找同一输入视图中重复规范化、拼接和查表的调用链，优先自然复用已规范化表示及已有句柄。
不能只把路径换成字符串或全局 ID 就宣称解决问题，也不能缓存授权结果、跳过根目录边界或产物内容核对。

### 第三优先级：重复遍历与遍历栈分配

crates/notist-core/src/item.rs:689 的 descendants 每次 vec![self]，然后 extend children。
这一通用辅助操作产生约 464 万次 malloc；就算单次很便宜，调用总量也足以形成 CPU 热点。
求值结构检查、正文链接与嵌入检查、标题取文等都有树访问。先检查可合并的遍历职责及可复用的工作空间，再考虑容器调整。
必须保留遍历顺序、所有来源／链接检查，不能改成可能无界溢出的递归以换掉堆栈。

### 暂不优先

- 扩大模块或数据解析缓存：实际未命中工作已经很少。
- 全面 FieldId／Symbol／特化键重构：特化键约 1.5% CPU，优先级低于容器和路径；不排除后续小型实验。
- 最终页面模板并行化：阶段占比不足 1%，不能解决主要串行阶段。
- 无证据地更换 allocator 或并行化求值：可能掩盖对象 churn，且会带来内存、缓存共享和输入视图语义成本。

## 边界与复现

本轮没有测增量编辑、serve 响应、LSP／Worker 交互、不同内容复杂度或不同规模站点，不能将本次排序外推为所有操作的结论。
也没有精确 off-CPU、磁盘系统调用或硬件缓存 miss 分解；不能用 wall − user − system 推算 I/O 时间。

在提交 9a3c5f7 上使用 tools/profile_hotspots.py 的 prepare、build、measure、cpu、allocations、verify，均传入新的 --out；分析使用 tools/analyze_hotspots.py --out。
prepare 后将 site 符号链接替换为独立输入副本、排除 dist，再开始构建和测量；本次首轮因此确为向空产物目录发布。
依赖的冻结基准、采样库绝对路径和二进制摘要见 manifest.json；工具副本见 reproducer。
