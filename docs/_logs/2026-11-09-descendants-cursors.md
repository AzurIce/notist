## 实现

crates/notist-core/src/item.rs：

- 保留先根、从左到右的深度优先顺序，返回原节点引用，根节点包含在内。
- 当前层使用借用的孩子切片迭代器，不再一次把所有兄弟压入节点栈。
- 遇到有孩子的节点，仅当父游标还有兄弟待访问时才保存父游标；单孩子链不需要保存祖先游标。
- 待恢复游标使用 SmallVec，内联 8 项；超出容量后使用堆，不改成递归，不限制可遍历深度。
- 构造及 next 路径标记 inline，让跨 crate 的调用方可以内联和消除不必要的状态搬运。
- 对外方法签名、find、来源、字段、预算和节点身份语义不变。

空间由待恢复的分支深度决定，不随同一层的兄弟数量增长。内联容量没有宣称经过全局调优。
smallvec 原已存在于 Cargo.lock；本次增加 notist-core 的直接依赖，没有升级其版本。

## 回归覆盖

crates/notist-core/src/item.rs 的 traversal_tests：

- 混合树的先根顺序与引用身份，以及 find 的包含根／找不到行为。
- 4,096 个兄弟的宽树保持顺序，游标栈不溢出内联存储。
- 深度 4,096 的分支树触发堆回退，遍历本身无递归；测试清理也采用迭代方式，避免混入节点递归销毁问题。
- 单节点只访问一次，多次调用耗尽迭代器保持 None。

crates/notist-core/tests/descendants_alloc.rs：

- 独立测试二进制以线程局部开关记录 System 分配 API，仅测遍历，不包含树构造和销毁。
- 单节点、4,096 个兄弟的浅树、嵌套链均为零分配；深度 128 的单孩子链也为零分配。
- 深度 128 的分支树正常触发堆分配并访问所有节点。

全工作区命令：cargo test --workspace --locked --offline -j2 -- --test-threads=2。
测试使用 CARGO_INCREMENTAL=0、CARGO_PROFILE_DEV_DEBUG=0、CARGO_PROFILE_TEST_DEBUG=0，以限制磁盘使用。
磁盘不足导致的链接失败及冻结副本缺少 target 临时目录导致的失败日志均保留；补建空目录后完整重跑成功，没有跳过失败测试。

## 整站测量

基线使用既有冻结普通 release 二进制，候选由本次冻结源码、独立 Cargo target 构建。
二者均使用 release、debug=1、incremental=0、jobs=2；计时版本无分配探针。
独立站点副本，前后各预热一次；随后 7 对测量，每对交替运行顺序。输出核对在计时结束后执行。
普通测量已有输出目录，发布主要比较产物，而非每轮首次写出站点；没有清空操作系统缓存。

“配对比值中位数”和“两组中位数之比”是不同统计量，不混称。样本来自同一台机器的一轮局部实验，没有做独立机器重复。

独立分配诊断各运行一次，不纳入 wall 对比。包装器调用原 glibc allocator，只对指定 Rust 父进程启用，不统计扩展子进程及未拦截的对齐分配入口。

| 成功 API 调用 | 基线 | 游标实现 |

这些是本次进程调用总数，不是存活对象数，也不表示每次 realloc 都物理复制；多线程通路的调用总量可能随运行有所波动。
