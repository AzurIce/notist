# SourceId32：来源身份符号化首轮实验

## 范围与状态

用户指定先采用 32 位并实现测量。基于 c722ecb 的 Item／闭包内核，只改来源表示及来源表共享，不包含 DefId、BindingId、参数字典、资源路径或站点生命周期优化。

这是性能实验初版，不是此前可回收来源数据库方案的完整落地。路径身份暂采用进程级 interner，永久保留出现过的精确来源名；正文仍由每份 Analysis／Evaluation 的 Sources 快照持有，不进入全局池。没有自动提交或推送。

## 实现

- `SourceId(NonZeroU32)`：4 字节，Option 也是 4 字节；私有构造，不公开裸数字，不复用编号；编号溢出检查后明确失败，不回绕。
- 精确文字唯一化，不新增 realpath、大小写折叠或隐式路径规范化。沿用宿主已有的逻辑来源名；不同根由宿主提供不同名字。本轮未新增来源命名空间或匿名 fresh identity API。
- 登记使用读锁快路径、写锁二次检查。Copy、同类型 Eq 和 Hash 仅操作编号；解析名字时访问全局表。名字登记和解析并非零成本，不在每个内容调用上重新登记来源。
- Ord 保留原路径文字字典序，避免有序索引和导出顺序随编号分配次序变化。因此不能声称消除了所有来源文字比较。
- TypedExpr、Invocation、CodeBody／CodeModule、Origin、SourceLocation、内部诊断及读取调用位置改用 ID。
- Sources 变为共享 COW 来源表，键为 SourceId、值为共享正文。分析和求值 clone 来源表不再逐项复制路径键；新增来源时分离。外部按名字查询支持非登记式查找，miss 不增长 interner。
- SourceId 不实现 Borrow<str>：其整数哈希与字符串字节哈希不同，不满足 Borrow 的哈希契约。Sources 通过显式查询适配支持 ID／字符串，不用不正确的 Borrow 实现迎合容器接口。
- wire／SourceId Debug 仍输出路径文字，Sources wire 仍为按文字顺序的路径→正文对象。裸树拆包后仍可序列化路径；代价是路径身份池不能回收。
- 相对资源解析仍在原有边界取路径；授权、输入批次、模块缓存的正文／配置／前端键不变。

## 生命周期限制

同一路径的新旧 Analysis 使用相同 ID，各自保留不同正文。旧结果不会因为全局 interner 而读取新正文；全局池不提供“最新源码”。Sources clone 后修改有 COW 隔离，已有句柄／正文一致性检查仍保留。

本轮保留既有来源表插入／合并行为，没有新增不兼容版本的合并拒绝契约。也没有完成弱唯一化、来源域、匿名来源身份、回收型 resolver／contextual serde 等完整设计。长期处理无界新路径或不可信来源名的服务不能据此声称内存有界；路径 metadata 的回收应在生产定型前继续评估。

## 结构布局

同一工具链、相应冻结源码的 core release 构建，用 `tools/source_id_layout.rs` 实测；不是根据字段大小推算。单位：字节。

| 结构 | c722ecb | SourceId32 |
|---|---:|---:|
| Node | 136 | 128 |
| Origin | 32 | 24 |
| SourceLocation | 24 | 12 |
| Invocation | 208 | 184 |
| TypedExpr | 160 | 136 |
| Diagnostic | 64 | 40 |

整个 Node 只缩小 8 字节，不能把来源字段从字符串变 4 字节的差值直接乘全部节点来声称 RSS 降幅。内存效果还取决于临时分配、共享表、容器容量、分配器及全站驻留。

## 测量方法与证据

权威 cohort：`/tmp/opencode/notist-source-id32-20261107-measured/`。

沿用此前完整 icexiv-db 冻结输入：51,225 物品页、513 目录页、1 首页；53,102 个输入文件／711,605,507 字节，预期 78,004 个产物／451,812,631 字节。consumer 原 checkout、输出和锁不修改。

两版在相同 release 编译参数下重新构建。workspace 构建产物在 cohort 自有 target 中按包清理以避免复制源码路径／mtime 导致的陈旧产物复用；复用的是独立试验 target 的依赖缓存，不借用原 consumer 或生产 checkout 的产物。

首次发布单列；随后五组交错 clean 配对，计时使用父进程 wall 与 wait4 RSS／CPU；每次都是新 CLI 进程，文件系统缓存不受控，不称为冷盘。所有完整输出路径、长度和 SHA-256 校验在计时之外。

另以 glibc malloc/calloc/realloc/free API 观察器各跑两次；只观察目标 Rust 可执行文件，不替换分配器，不把诊断时长当性能证据。realloc 包含在 allocations 中，请求字节是流量而非 live heap／RSS，未覆盖 aligned 入口及 libc 内部调用。

本批衡量 SourceId32 加来源表 COW 的整体变化，不是 32 位对 64 位的对照，也不能把来源表共享收益全部归给整数位宽。

## Clean 整站 A/B

| 配对 | c722ecb（s） | SourceId32（s） |
|---|---:|---:|
| 1：前→后 | 9.5243 | 9.3167 |
| 2：后→前 | 9.4971 | 9.4157 |
| 3：前→后 | 9.4762 | 9.3479 |
| 4：后→前 | 9.6384 | 9.4475 |
| 5：前→后 | 9.4449 | 9.3594 |
| 中位数 | 9.4971 | 9.3594 |

wall 中位数下降 **0.1378 s／1.45%**；五组分别少约 81–208 ms，方向一致，但样本少、未锁频且存在背景负载，不宣称已证明普遍或大幅加速。user CPU 中位数 8.7372→8.6213 s（−1.33%）。

峰值 RSS 中位数 **3,372,912→3,324,708 KiB**，减少 **47.07 MiB／1.43%**，包括进程级名字 interner 本身的成本。没有达到低内存站点架构目标，不能把分配字节流量或 struct 大小直接当 RSS。

首次发布 10.0574 s 单列，不进入重复发布 A/B。所有成功构建的 78,004 个完整产物与同一权威 inventory 一致。临时 cohort 的绝对路径前缀不同于真实 checkout，来源文字相关字节量也受路径长度影响。

## 分配诊断

每版两次交错，计数完全相同；下面是一次完整构建的目标进程 API 流量：

| 指标 | c722ecb | SourceId32 | 变化 |
|---|---:|---:|---:|
| allocations（含 realloc） | 195,962,909 | 195,236,821 | −726,088／−0.37% |
| 累计请求字节 | 14,026,348,387 | 13,756,259,080 | −270,089,307／−1.93% |
| frees | 181,492,815 | 180,714,974 | −0.43% |
| reallocations | 14,468,426 | 14,468,440 | 基本不变 |

说明来源表示确实减少了临时分配和存储，但绝大多数高频分配仍存在；它没有消除 execute 的参数字典、函数分派或内容配方／节点构造。**可以保留为有小幅收益的来源表示实验，不能说字符串问题已解决或整站得到大幅提速。** 回收与身份域仍须在生产定型前单独处理。

## 验证结果

- 全 workspace、全特性：788 项 Rust 测试／文档测试通过，89 个测试目标。
- core／eval／pipeline 无默认特性：153 项通过。
- Python profiling 工具：57 项通过。
- 51,225 物品页、513 目录页及全部本地 HTML 链接校验通过；冻结源码／二进制／重现工具／输入哈希通过，全部输出 inventory 一致，原 consumer 输入未变，当前生产 Rust 源码与冻结候选一致。
- 新增覆盖 70,000 个来源、并发登记、精确文字身份、不同根、Sources COW、查询 miss 不登记、新旧正文快照隔离、文字排序与 tree／diagnostic／source-map wire。
- 顶层 notist 无默认特性仍被既有 `src/json.rs` 的 TypedExpr serde 使用阻挡；在未修改的 c722ecb 冻结源码上复现同一错误，不声称全工作区无默认特性通过。本轮 preview 的来源投影使用字符串视图，不增加 SourceId serde 的无特性依赖。
- 严格 Clippy 被既有 item.rs collapsible_if、shared.rs box_collection 阻挡；临时允许后还遇到既有 present_call 参数个数 lint。未修改这些无关实现，也不把允许 lint 当成修复或严格通过。

## 复现

```sh
OUT=/tmp/opencode/notist-source-id32-fresh
python3 tools/profile_source_id.py prepare --out "$OUT" --reference /path/to/frozen-kernel-cohort
python3 tools/profile_source_id.py build --out "$OUT"
python3 tools/profile_source_id.py measure --out "$OUT"
python3 tools/profile_source_id.py allocations --out "$OUT"
```

该驱动依赖已有、完整且 guard 通过的 kernel cohort；不是任意 consumer 的通用 benchmark。工具代码、源码和输入指纹由 manifest 冻结。reference 的 normal 必须是 c722ecb 基线。不要并行构建或测量同一 target／site，也不要覆盖旧 samples。

证据索引：`manifest.json`、`workspace.patch`、`samples.json`、`summary.json`、`allocation-samples.json`、`allocation-summary.json`、`layouts.json`、`test-summary.json`、`semantic-check.txt`、`integrity-check.json` 和 `logs/`。此前未计时的准备／过渡目录不是结论依据，不与该 cohort 混用。
