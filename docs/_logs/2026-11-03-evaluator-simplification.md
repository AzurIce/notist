# 求值器局部简化与同批验证

## 结论

三项局部简化均保留。本批 15 个负载／发布状态组合没有中位数回退，宽导出改善最明确；这不等于所有输入或每次运行都保证更快。

- 宽导出：same 加速 **1.175×**，耗时减少 **14.9%**；replace 为 **1.143×**，first 为 **1.091×**。
- 无模块正文为 **1.056–1.067×**，共享图为 **1.060–1.100×**；各自正式配对样本中 after 均更快，但样本量小，不主张统计显著性。
- 私有图为 **1.008–1.046×**，仍属小幅变化，不能据此宣称私有模块编译或缓存持有问题已经解决。
- XIV 为 **1.013–1.026×**，范围明显重叠，按基本持平处理；尤其 first 的三组配对只有一组 after 更快，不能只看中位数之比宣称稳定收益。
- **145 次完整构建**，累计核对 **1,561,360 个文件指纹**、**1,560,867 份 HTML**，全部与原完整清单一致。这些是多轮验收总数，不是唯一页面数。

## 实施范围

本轮在上一轮未提交优化补丁上继续做三项局部简化，生产增量只涉及 crates/notist-pipeline/src/code/check.rs 与 eval.rs：

1. **只读函数体借用**：实例检查直接借用 Context 中的 CodeBody，不再复制未检查的 Expr；诊断仍按所属结果复制。不增加 Arc 层。
2. **单节点返回单节点**：present_node／present_call 返回 Item，bind_content 逐项 push，不再通过单元素 Vec 传递这些局部结果。森林与 Runtime Content 的表示保持原样；execute 的挂载边界容器并未全部消除。
3. **递归返回摘要**：bind_content 返回森林及正常节点数；present／repeat 返回森林及 ContentSummary，present_node／present_call 返回节点及摘要。父层合并计数，repeat 通过 failed 判断失败，不重新扫描已构造子树。

ContentSummary 只有 nodes 与 failed，是当前返回值的局部信息，不写入 Item，不是持久缓存。显式共享内容插值处仍保留一次 content_count；没有为了消灭这次扫描而扩大 Runtime::Content。

绑定与呈现不合并，保留 Analysis 不变、重复挂载隔离、延迟内容、扩展执行目标、来源与诊断、恢复节点、逻辑读取顺序、累计额度、依赖及 NeedResources。没有新增缓存、实例 ID、spool、调度器或 allocator 替换。

每种负载／状态／二进制另有一次预热，另先做五次 seed，共 145 次完整构建。逐文件验收在每个子进程退出后进行，不计入 CLI wall。普通、插桩与多核不混算；本轮不新增插桩或多核计时。
