# 设计概览与核心哲学

Notist 以独立、极简的语言内核 `crates/notist-core` 与纯编译编排层 `notist` 为中心，下游消费层（HTML 渲染、SSG、CLI、LSP）逐层叠加。以下五条核心原则是架构设计的硬性边界，演进过程中不得破坏：

## 1. 前后端无关，严禁渲染与宿主细节入侵语言

- **前端无关**：Markdown 等文档源格式通过 `DocumentFrontend` 边界降级为与 `.not` 模块统一的 `notist_core::Module` IR，语言内核不绑定任何特定标记前端。
- **后端无关**：`notist-core` 的终点是不可变的内容树（`Inline` / `Block`），`notist::Compiler` 的终点是求值后的内容树集合。任何特定输出后端的细节（HTML 专属属性如 `loading` / `decoding` / `width` / `height`、CSS、JS、Web Component 打包、Tera 模板、Sass、站点路由）**不得泄露进 `.not` 语言语义或 `@(...)` 约定**。
  - `@(...)` 与 `.with_attr(...)` 只表达文档语义与结构元数据（如 `id`、`title`、`collapsed`、`agents`），不作为任意 HTML 属性的透传通道。
  - 通用渲染优化归 HTML 渲染层；带特定前端行为的元素归外部组件（`CustomNode` + 宿主实现）或声明替换。
- **零隐式 IO**：`notist-core` 不做任何文件系统或网络 IO；外部只读数据经由显式 `DataHost` / `Resources` 边界传入，产物发布由宿主统一校验与执行。

## 2. 强静态类型，拒绝隐式转换

- **绝不做隐式类型转换**：`Inline` 与 `Block`、`Int` 与 `Float`、标量与 `String` 之间必须显式转换（如 `para(...)`、`text(...)`、`to_string()`），不引入隐式 coercion 或弱类型回退。
- **定义点全量静态检查与检查屏障**：所有模块中未调用的函数、泛型函数体及 `match` 分支都在编译期静态检查；任何静态错误都会阻断求值，保证不进入半截运行态。
- **文档与逻辑分离**：文档入口顶层保持声明式，控制流与组件定义集中在 `.not` 代码模块中。

## 3. 一切 Markup 皆为组件函数的语法糖

- 所有内置标记语法（标题、段落、列表、强调、数学公式等）均在检查期直接降糖为内置 `notist` 模块下的正式声明调用（绑定确定 `DeclId` 与签名），不受局部词法遮蔽影响。
- 语言级替换在类型检查完成后的 `DeclId` 层按静态签名契约做特化重绑定，严格单遍求值，不采用“求值后再遍历重算”或“裸文本/Parse AST 替换”。

## 4. 不可变值与诚实的 API 边界

- 内容树（`Inline` / `Block`）、属性（`Attrs`）、列表与 JSON 均为不可变、结构共享的值；树变换（如 `sectionize()`、`rewrite_*`）返回新值而不原地修改。
- **数据构造与执行显式分离**：纯计划与数据结构只用诚实的数据构造方式表达，不用 `write` / `copy` 等命令式副作用动词暗中构造延迟计划；实际执行由显式的执行入口完成。

## 5. 面向工具链的分层设计

- 解析、接口提取、模块体检查、可达特化与求值明确分层，使 SSG 与 LSP 能在源码不完整且不求值的情况下稳定提供精确的类型感知能力；特化期声明替换不影响源码级跳转与诊断定位。
