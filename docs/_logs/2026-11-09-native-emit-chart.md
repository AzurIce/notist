计数关闭、只保留边界计时的三次 native 诊断运行，run.total 为 2.541／2.550／2.565 秒，中位数 2.550 秒。
其中 run.present 中位数 2.393 秒，来源视图与校验约 0.118 秒；首次绑定和 Evaluator 初始化合计约 0.014 秒。
旧诊断 run 中位数为 2.749 秒。可将其作为前后过程参考，但这是非交错、带探针的测量，不声称它就是 native 的精确求值收益。

本轮五组普通 release 交错 A/B 均更快，配对 wall 变化为 -0.71%、-13.63%、-5.55%、-2.97%、-1.78%，中位数 -2.97%。
两组 wall 中位数为 7.819／7.446 秒；简单相除与配对统计不是一个量。
有明显机器波动，全部保留，因此不承诺固定百分比；已有独立 native 实验的五对中位数为 -2.53%，方向一致。
计数关闭探针控制也有明显波动，不据诊断版本偶尔更快宣称探针无开销。

## 现在的路径与剩余问题

立即挂载 native 构造的通路为：

```text
present_call
  → execute_inner：实参、字段、实现查询和校验
  → Execution::Element
  → present_element：子内容、结构校验、来源链
  → 写入调用者 out
```

原先 Content::one 的单元素计划及其外层 present／临时节点 Vec 已省去。
子内容仍需求值与发射；通用实参字段、共享 children、实例元数据、数据 API 及对象生命周期仍有成本。
因此原图中这条中间计划往返不再是待修问题，剩余优化应聚焦参数／字段装配、空子内容以及共享容器的构造与销毁。
当前剩余 present 输入中，空片段约 49.4%，单元素约 29.5%；比例变化主要因为 native 的 406 万个单元素包装已被去掉，不能继续沿用旧图的 89.0%。
