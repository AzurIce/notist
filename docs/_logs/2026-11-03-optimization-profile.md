# 架构优化实现与同批性能对照

## 结论与范围

生产基线为 `214de5fec5ea796a047024510566168e1fa81d08`，优化侧是当前**未提交补丁**，不是另一个提交。普通 release 二进制在同一批次重新测量前后两侧，没有套用上一轮基线秒数。

- 输出不变的完整重建：四种正文／模块负载加速 **1.53–4.60 倍**；XIV 加速 **1.30 倍**。
- XIV 强制整站替换：**1.01 倍，基本持平**，不能据此声称稳定改善真实变更构建。
- XIV 首次构建：**1.11 倍**；四核无变化重建为独立补充，不混入单核结果。
- 主批次共 **213 次完整成功构建**，核对 **3,080,809 个文件指纹**，包括 **3,080,057 份 HTML**；各次最终输出均与原始完整清单一致。这些数字包含多轮重复验收，不是唯一页面数。
- 另有 **12 次优化后专用发布检查探针**，核对 416,048 个文件指纹；它们仅用于定位新检查成本，不加入前后加速比。两批合计 225 次、3,496,857 个文件指纹，均保持输出一致。
- 完整真实 XIV DB、页面枚举、所有正文、消费者、`site.data` 结构及依赖锁均未改变。SSG 输入请求及 Data 缓存预算的既有政策也未改变，不算作本次优化。

## 实施边界

### 已实施

1. **树所有权**：绑定／capture 只复制正在重建的节点边界，不先深拷贝马上替换的 children／pending；内部 present 消费已经拥有的森林；唯一持有的 Runtime Content 直接取得所有权。Analysis 保持不变，重复挂载继续隔离。
2. **共享调用计划**：CheckedProgram 与 InstanceRecord 使用 Arc／写时复制，调用共享 checked body；按扩展映射后的实际目标决定是否构造 Code Scope，原生调用避免无用的词法输入与 children 副本。
3. **宿主批处理**：共享 UTF-8 源码、批次配置解析与成功模块装配缓存；DocumentHandle 绑定 Vault 配置身份、路径、源码快照和 Environment，贯穿 SSG 求值及 HTML 绑定。模块图命中仍按原 DFS 顺序请求源码并计费。
4. **有界检查计划复用**：仅复用从空程序开始、无诊断且无 Data retention 的完整成功 Code 计划；每个 Context 基础最多 32 个计划／8192 个记录。安装模块或改写 Code 作用域时分离缓存，不合并多余实例绕过限制。
5. **路径与产物**：借用序列化站点扩展请求；消费扩展验证得到的 Route；生成输出先预留槽位、再一次填入字节；建立按输出路径和目录别名查询的链接索引，保持源身份优先。
6. **发布与模板**：暂存时去重创建父目录；实际有界比较全部旧输出字节及精确目录项，完全一致才跳过替换。至少 1024 页时，仅已准备的不可变模板工作可并行，最多 8 worker，按顺序合并产物与首个错误。

### 未实施，不能算作已完成

- 参数槽位与实例 ID：求值器仍使用现有命名 Scope 和实例键，没有重写 IR 调用表示。
- 产物 spool／staging sink：BuildOutput 仍拥有完整产物字节，未改变输出 API 与 IO 职责，也未测得内存下降。
- 逐文件增量发布：当前只优化**整站输出完全相同**的情况；任意差异、额外目录项、symlink 或比较失败仍执行整站暂存、替换和同步清旧。
- 全管线并行：输入、文档 hooks、分析、求值和发布保持既定顺序；只有模板任务并行。没有异步清理、移出计时的清旧或并行 Vault。

因此本轮完成了 P0、P1 和上述明确范围的 P2，不能概括为所有 P2 设想均已落地。

## 发布：no-op 的收益与真实替换的限制

无变化 XIV 探针：完整 publish 为 **884.743 → 328.573 ms**。旧侧写暂存 473.074、清旧 411.455；新侧完整字节／目录比较为 223.974，除此之外的发布检查成本也计入 publish，不能仅用 compare 代表全部发布成本。

强制替换 XIV 探针：publish 为 **930.274 → 1052.572 ms**；写暂存为 494.213 → 449.990，清旧为 435.859 → 479.590，优化侧还承担了 11.481 的失败 no-op 比较。目录去重确实删除了冗余系统调用，但没有消除逐文件写出与旧目录删除，也没有得到稳定的端到端替换加速。

独立 strace 控制如下；均包含 CLI 及扩展子进程，不能当作仅发布函数的精确调用数。trace wall 不参与性能结论。

## 四核补充

仅普通二进制、XIV 无变化重建，固定 CPU 8–11，独立预热后各三轮：前侧中位数 **4.020495 s**，后侧 **2.891784 s**，加速 **1.390 倍**。前侧范围为 3.913935–5.612445，后侧为 2.867420–2.913240；前侧一个慢样本保留。

优化后四核与优化后单核无变化队列中位数之比为 1.068，但两队列分时段运行，**不是隔离模板并行开关的严格 A/B**。不能将 1.390 倍全算为并行收益，也不报告线程局部探针的跨 worker 总计。
