# 边界字段分配与调用恢复所有权（2026-11-04）

接续 [签名 COW 与实例复用](2026-11-04-runtime-cow.md)。本次只处理调用失败恢复的备份，不更改公开 Item／Origin／FunctionId 类型，不改外层 present 的总节点预算恢复，不引入整树 COW、结果缓存或跨轮复用。

## 1. 先测字段，而非猜测哪个 clone 最贵

在独立源码副本中，分别标记 bind、present 恢复、调用恢复、capture 的 item_shell，并将七个字段的 clone 放进固定容量记录器。观察器将分配转发给相同的 System allocator，不分配记账容器、不对每次操作计时；普通 A/B 二进制不链接该观察器。

## 2. 选择最小的所有权改进

原来的 present_call 已经拥有 Item，却在交给 execute 前另做完整 item_shell，以便 execute 失败时恢复：

```text
拥有原边界 → 复制恢复备份 → 把原边界交给 execute
                             ├─ 成功：丢弃备份
                             └─ 失败：丢弃原边界，使用备份
```

现在由调用方保留 `Option<Item>`，execute 借用这个槽位。参数、实现、返回类型等可能产生 Result 错误的操作全部完成后，才 take 边界并组装成功结果：

```text
拥有原边界 → 暂借 execute
              ├─ 成功：take 原边界，移入结果
              └─ 失败：原边界仍由调用方拥有，直接恢复
```

因此不需要为每次成功调用提前复制身份和来源，也不需要多包一层 Arc/COW。与上一批相同，优先移走不必要的复制，而非让所有复制都变成引用计数。

这不是对求值器状态做事务回滚：已经发生的逻辑读取、步骤、累计额度与诊断仍按原顺序处理，不退款、不吞掉硬预算。原边界 children 在执行前已移出，失败时本就应清空；公开恢复树仍保留原 ctor、instance、字段、注解、来源、span、level，target 与诊断继续由原 error/error_at 逻辑产生。

所有生产改动及新增回归只在 `crates/notist-pipeline/src/code/eval.rs`。回归覆盖两个 frontend，检查调用前拒绝、参数求值失败、内容返回类型违约、数据返回契约违约四条路径；特意附加字段、注解、来源扩展和 children，验证失败保留正确边界而非部分执行产物。现有循环、资源读取、深度和内容额度测试继续参与验收。

## 4. 验收结果

### 精确归因复核

after 字段观察器中，调用恢复场景的 shell、分配及请求字节全部为零；**其它三个场景的每个字段记录均与 before 完全一致**。总 shell 从 **16,784,043 → 12,667,567**，shell 内分配事件从 **85,293,422 → 64,246,960**，请求字节从 **2,694,235,862 → 1,943,751,887**。

因此可以确认消除的是预期的那一类备份，而非少处理了 bind、挂载或来源。上述仍仅为 shell 范围的分配归因，不宣称是整个 Rust 进程的分配总量。两版字段探针分别用时 19.239s、21.260s，显然受观察器和环境影响，**不用于性能结论**。

### 普通二进制：六轮配对

| 中位数 | before | after |
| --- | ---: | ---: |
| wall | **14.234s** | **13.698s** |
| user | 12.731s | 12.207s |
| system | 1.711s | 1.705s |

两个 wall 中位数少 **0.536s**。逐轮配对的耗时降幅为 `3.31 / 3.65 / 4.16 / 2.68 / 4.02 / 4.15%`，中位数 **3.84%**，六轮均更快；六样本配对中位数的描述性 bootstrap 95% 区间为 **3.00–4.16%**。

CPU 频率和系统任务没有完全隔离；保留全部样本，正式主组记录 1 次 major fault。after 的 warmup 曾为 16.330s，按预先规定的 warmup 分组保留、不计入主统计，不事后从正式组删除慢样本。

### 正确性与内存

- after workspace 默认 **734 项**、全特性 **743 项**通过，74 个 test target，零警告；核心／管线无默认特性 **130 项**通过。
- 字段观察器 Rust 单测 1 项、冻结／插桩工具 Python 单测 2 项通过；原通用验收工具单测不改。
- **21 次全量构建的全部 78,004 个输出文件 SHA-256 一致**：普通验收 19 次、字段探针 2 次。四组完整 analysis/evaluation JSON 前后相同；消费者自己的详情／目录／本地 HTML 链接检查通过。
