# S0：骨架竖切（段落 + heading 走通全管线）

起点：空 crate。终点：lexer → CST → AST → core 树 → dump CLI + snapshot 测试的完整管线，只认段落和 heading 两种构造。

这份路线把"看起来是一整个 S0"拆成九步，每步都可编译、可见输出、可验收。参考实现在本地分支 `s0-reference`（提交 `17b001f`，各步标注的文件即该提交内的路径）——先自己写，卡住了用 `git show s0-reference:src/parser.rs` 对照，看完关掉重写。

## 工作方式

- 每步只引入一个新概念；完成即提交，仓库保持绿。
- 先想"这一步的输出长什么样"，写到能打印出来看，再往下走。
- 歧义不停留：任何"这种情况该怎么办"的瞬间，把规则写进 `docs/draft.not` 再实现。
- 不需要编译原理。需要的新概念在各步标注，总共七个：token、span、lossless、builder、peek/stop 条件、AST 视图、语义树。

## Step 0 — 项目骨架

- 内容：`Cargo.toml` 加依赖 `rowan`、`insta`（dev）；建 `src/lib.rs` + 空模块文件；`main.rs` 只留 hello。
- 验收：`cargo build`、`cargo test` 绿。

## Step 1 — lexer（纯函数，不碰 rowan）

- 概念：**token**（带种类的文本切片）、**span**（字节偏移）。
- 内容：四种 token——`Eq`（`=` 串）、`Whitespace`（空格/制表符）、`Text`、`Newline`（含 `\r\n`）。`lex(&str) -> Vec<(Kind, &str)>`，切片直接借用源文本。
- Rust 要点：`find`/`trim_start_matches` 返回的都是字节偏移，切片必须落在字符边界上——本设计的特殊字符全是 ASCII，天然安全。
- 验收：几个小字符串的单元测试，打印 token 流肉眼检查。

## Step 2 — rowan 样板（一次性仪式）

- 内容：`SyntaxKind` 枚举（token 种类 + 将来的 node 种类，统一在一个枚举里，`#[repr(u16)]`）；`Language` impl（`kind_from_raw` / `kind_to_raw`）；`SyntaxNode`/`SyntaxToken` 类型别名。
- 说明：这是全项目唯一"看不懂先抄"的部分。它换来：tree 自动计算 span、trivia 可保留、将来 LSP 增量复用。
- 验收：编译通过即可。（参考：`src/syntax.rs`）

## Step 3 — builder 初体验（可选但推荐）

- 概念：**builder**（`GreenNodeBuilder`）、**lossless**（每个 token 必须进树，否则树拼不回源文本）。
- 内容：不写任何文法，只把 Step 1 的 token 流逐个 `builder.token()` 喂进去，外面包一个 Document node，`println!("{:#?}", node)` 看 rowan 自动打印的树。
- 验收：打印出平坦的 Document 树，每个 token 带自动计算的 range；自验：所有 token 文本拼接 == 源文件。

## Step 4 — parser 骨架 + 段落

- 概念：**peek**（看不消费）、**stop 条件**（子解析器的契约）。
- 内容：`Parser` 结构（tokens/pos/builder）+ `cur`/`peek`/`eat`；文法：Document = 段落流，段落 = 连续非空行，空行（含纯空白行）分隔。先不做 heading。
- 要点：`line_ends_block` 这类"换行后是什么"的判定是唯一需要 lookahead 的地方；空行的新行符归属 Document（块的 span 恰好是内容范围）。
- 验收：多段落、纯空白行分隔的用例，树形正确、lossless 自验通过。（参考：`src/parser.rs`）

## Step 5 — heading

- 内容：块起始处 `Eq` + `Whitespace` → heading，层级 = `Eq` 长度；`=x`（无空格）不是 heading；段落遇到 heading 行要收尾。空标题（`= ` 后无内容）合法。
- 用例：层级 1–3、`=x`、heading 截断段落、空标题。
- 验收：全部用例树形正确。

## Step 6 — AST 视图

- 概念：**AST 视图**（typed newtype 包在 CST node 上，不存数据，只做导航）。
- 内容：`Document`/`Block`/`Heading`/`Paragraph` 包装 + 访问器：`blocks()`、`level()`（找 Eq token 取长度）、`content_tokens()`（跳过 marker）、`lines()`（按 Newline 分组）。
- 验收：纯新增代码，原有测试不变绿。（参考：`src/ast.rs`）

## Step 7 — core Item 树（纯数据）

- 概念：**语义树**——节点是构造器调用结果（Ctor 封闭枚举 + fields + children + span），不再是语法构造。
- 内容：`Ctor`（Doc/Paragraph/Heading/Text/SoftBreak）、`Value`（Unit/Bool/Int/Float/Str）、`Dict`（保插入序）、`Item` + 构造辅助。
- 要点：Ctor 用枚举不用字符串——typo 是编译错误而不是运行时静默。
- 验收：编译通过，可手工构造并 debug 打印。（参考：`src/item.rs`）

## Step 8 — lower + dump + CLI

- 内容：AST → Item：行 trim 两端空白成 Text item（span 收拢到非空白 token），行间插 SoftBreak（span = 两个 text 之间的间隙，即换行符）；heading 带 `:level`。dump 成 `(ctor @start..end :field value ..)` 缩进树。`main.rs`：默认 dump core 树，`--cst` 打印 rowan 树。
- 要点：trim 是 lower 的第一个"语义决定"——core 树的 span 必须精确到 trim 后的文本，这是"分析在 core、报错在 surface"纪律的起点。
- 验收：`notist corpus/paragraphs.not` 输出正确，span 抽查与源文件逐字节吻合。（参考：`src/lower.rs`、`src/dump.rs`）

## Step 9 — insta 测试骨架

- 内容：`tests/corpus.rs` 遍历 `corpus/*.not` 做 `insta::assert_snapshot!`；工作流：`INSTA_UPDATE=always cargo test` 生成/更新 → 人工 review 快照 diff → `cargo test` 确认绿。
- 用例（至少）：多级 heading、`=x` 非 heading、段内 soft break、纯空白行分段、空标题、空文件。
- 验收：快照全绿，且每个快照你都逐行核对过。（参考：`tests/corpus.rs`）

## 完成定义

- 任意合法输入（段落 + heading）都能 parse → lower → dump，且 CST 文本拼接 == 源文件。
- snapshot 全绿；`--cst` 与 core dump 两种视图可用。
- 此后每加一种构造（S1），只是往 lexer/parser/lower 里添分支，管线本身不再动。
